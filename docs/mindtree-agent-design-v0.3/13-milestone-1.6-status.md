# 里程碑 1.6 实施状态

更新时间：2026-07-15

## 目标

让自然记录、项目树、知识卡和历史沉淀能够被重新找到，并为 AI 提供少量、可解释、受限的跨导图上下文。

## 已完成

- 新增客户端纯领域检索内核，统一处理跨导图关键词、语义筛选、排序、草稿隔离和来源角色。
- 关键词覆盖节点主题、备注、链接和本地标签名称；同一节点只返回一条结果并标明命中字段。
- 结构化筛选覆盖导图范围、标签、标记、任务状态、优先级和沉淀来源/结果角色。
- `⌘F` 搜索保留“当前导图”默认行为，并可切换到“全部导图”。
- 搜索结果显示导图名称、完整节点路径和命中语义；跨图选择后切换导图并定位节点。
- 搜索筛选不修改导图、不改变布局，空关键词也可以只按语义条件检索。
- AI 助手和随手助手新增受限工作区检索：从问题与焦点主题提取少量关键词，最多返回 12 个相关节点。
- AI 检索排除当前导图和未转正草稿；不返回附件、整张无关导图或未命中原文；备注最多 600 字。
- MCP `mindtree_search_nodes` 支持主题、备注、链接、导图范围、标签 ID、标记、任务状态、优先级和沉淀来源角色。
- MCP 搜索返回导图版本、节点路径、语义字段和来源角色，且继续按当前账号隔离数据。
- MCP 应用沉淀时保存受影响节点 ID，因此新生成的长期资产可以被 `target` 角色检索。

## 产品与安全边界

- 客户端默认不在“全部导图”结果中展示随手记草稿；当前打开的草稿仍可在当前导图范围内搜索。
- AI 相关节点只是参考上下文，提示词明确禁止其覆盖当前导图事实。
- AI 不会因为检索结果自动修改任何导图；写入仍沿用候选、预览、确认和撤销流程。
- MCP 搜索是只读工具；结构化筛选不会扩大 MCP 的写权限。
- 本地标签名称不在服务端自动同步；MCP 第一版按稳定的标签 ID 过滤。
- 1.6 不引入向量数据库、嵌入模型、后台全量索引或自动历史整理。

## 验证

- 客户端检索内核覆盖跨图排序、备注/链接、标签名、组合筛选、来源角色、草稿隔离和语义返回。
- 搜索弹窗覆盖默认当前导图、切换全部导图、跨图回调和无关键词语义筛选。
- AI 检索覆盖跨图相关节点召回和无关节点排除。
- MCP 端到端覆盖结构化筛选、节点路径、语义字段、来源节点和生成结果检索。
- 客户端 33 个测试文件、132 项测试通过；服务端 5 个测试文件、19 项测试通过。
- 客户端与服务端 TypeScript 生产构建通过。
