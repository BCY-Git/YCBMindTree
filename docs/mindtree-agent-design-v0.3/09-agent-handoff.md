# 编码 Agent 交接与执行规则

## 1. 任务目标

在 MindTree 0.2.2 基础上实现智能沉淀 MVP。首要验证：用户保持自然记录习惯时，系统能否识别高价值内容并经确认回流到项目或知识结构。

## 2. 开工前必须完成

1. 阅读本设计包指定文档。
2. 阅读项目中的 `docs/architecture.md`、`docs/product-requirements.md`、`docs/release-0.2.2.md`。
3. 检查工作区是否有 `AGENTS.md`，若存在则遵守。
4. 运行当前测试和构建，记录基线。
5. 检查未提交修改，不覆盖用户已有工作。
6. 先输出实施计划和 todo，再修改代码。

## 3. 实施原则

- UI 不直接修改文档节点。
- 所有持久化导图变更经过 Command executor。
- AI 输出是外部不可信数据，必须 Zod 校验。
- 模型只生成候选，不声称已经应用。
- 用户确认前不能写入导图。
- 原始源节点不得被覆盖或删除。
- 一次沉淀确认应构成一个可审查的变更单元。
- 优先复用现有类型、Store、AI 请求、预览和持久化能力。
- 不在本功能中顺便重构无关区域。

## 4. 实施顺序

严格按以下顺序推进，每一步完成后测试：

```text
领域类型与协议
→ 解析与校验
→ 重复检测与应用计划
→ 持久化批次
→ 上下文构建
→ AI 调用
→ 候选 UI
→ 单文档原子应用
→ 来源追踪
→ 跨文档回流
```

不要从 UI 开始把临时逻辑堆入 `AiAssistant.tsx`。

## 5. 必须向用户请求审查的节点

### Review 1：协议

展示：候选类型、动作、模型 JSON 示例、边界情况。

### Review 2：数据迁移

展示：Dexie 新表、备份策略、是否修改文档 schema。

### Review 3：交互

展示：候选单项、收件箱、差异预览和成功反馈。

### Review 4：单文档 MVP

用固定四类样本演示完整闭环。

### Review 5：跨文档

展示事务、版本冲突、导航和撤销方案后再实施。

## 6. 每个 todo 的完成标准

- 实现代码。
- 新增或更新测试。
- 运行相关测试。
- 检查类型错误。
- 不破坏既有行为。
- 更新相关设计或发布文档。
- 汇报完成内容、证据、限制和下一步。

## 7. 禁止自行扩大范围

未经用户确认，不得加入：

- 多 Agent。
- 向量数据库。
- 自动后台持续调用模型。
- 未确认写入。
- 全历史批量整理。
- 节点自动删除、合并和大范围移动。
- 全新状态管理框架。
- 大规模视觉重构。

## 8. 需要明确的剩余决策

实施中若现有代码无法直接确定，应由用户审查：

1. 未处理候选是否进入工作区备份。
2. 已应用来源是否随单图导出。
3. 第一版是否允许跨文档写入，或先只做当前文档。
4. 跨文档操作采用工作区级撤销还是补偿日志。
5. 默认分析范围是当前节点还是当前子树。
6. 低置信度候选默认是否选中。

建议默认：

- 候选进入工作区备份，单图导出不包含候选。
- 已应用来源进入工作区备份，单图导出第一版可不包含。
- 先交付单文档闭环，再做跨文档。
- 默认分析当前子树。
- 低置信度和可能重复候选默认不选中。

## 9. 最终交付报告格式

```markdown
## 已完成

## 关键设计决定

## 修改文件

## 测试与构建结果

## 尚未实现

## 已知风险

## 建议下一步
```
