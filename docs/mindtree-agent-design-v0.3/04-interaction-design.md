# 智能沉淀交互设计

## 1. 设计目标

- 不改变用户原有记录节奏。
- AI 在用户需要时出现，不持续占据画布。
- 候选审查应比手工搬运更省力。
- 始终让用户知道“来自哪里、准备写到哪里、会做什么”。

## 2. AI 助手中的新能力

在现有“询问 AI / 生成分支 / 生成计划 / 整理全图”旁增加：

```text
生成沉淀建议
```

点击前显示分析范围：

```text
范围：当前子树「7.14」
[当前节点] [当前子树]
```

不建议第一版默认分析整张大型导图。

## 3. 待沉淀收件箱

建议作为左侧 AI 助手中的独立折叠区，不新增第四栏。

单条候选展示：

```text
☑ 成果
AFSIM PPT 已完成并交付

来源：7.13周报 › 7.14 › 加班22:43…
动作：完成已有事项
去向：AFSIM项目 › PPT交付

[修改] [忽略]
```

必须展示：

- 类型
- 精炼标题
- 来源路径
- 动作
- 目标位置
- 风险提示（可能重复、目标不明确等）

“AI 判断理由”放在展开详情，不长期占用空间。

## 4. 审查操作

用户可：

- 勾选/取消候选。
- 修改候选类型。
- 修改动作。
- 搜索或选择目标文档与节点。
- 编辑写入标题或备注。
- 忽略候选。
- 批量确认选中项。

主操作：`预览并写入`。  
次操作：`全部稍后处理`。

## 5. 差异预览

确认前按操作展示变化：

```text
+ 新增：无人项目 › 问题 › 得分与行为不匹配
✓ 完成：AFSIM项目 › PPT交付
↳ 追加备注：地图瓦片路径
```

跨文档操作必须按目标文档分组显示。

## 6. 写入反馈

成功后：

```text
已沉淀 3 条内容，更新 2 份导图。
[查看结果] [撤销]
```

查看结果可以先打开目标文档并选中节点。跨文档整体撤销若当前架构难以支持，第一阶段应通过工作区级事务日志实现；不能用多个互不关联的普通撤销假装整体撤销。

## 7. 低打扰触发

第一版不自动调用模型，但可在以下时机显示本地提示：

- 随手记准备转正。
- 日期分支新增多个节点后。
- 完成了一组任务。
- 离开存在未处理候选的文档。

提示示例：

> 这段记录可能包含项目进展和待办，需要整理吗？

操作：`现在分析`、`稍后`、`不再提示此文档`。

## 8. 智能协作的后续入口

在项目节点菜单保留未来入口：

```text
围绕此节点开始协作
```

用户可选择探索、决策或交付；该功能不属于智能沉淀 MVP 的阻塞项。

## 9. 普通使用不受影响

- 没有配置 AI 时不出现错误阻塞。
- 未开启沉淀功能时，当前编辑和导出行为保持不变。
- 普通节点不显示新的永久徽章。
- 来源和 Agent 元数据默认放在详情或后台数据中。
