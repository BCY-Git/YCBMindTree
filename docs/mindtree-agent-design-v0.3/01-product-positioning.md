# 产品定位、核心价值与设计初心

## 1. 产品定位

MindTree 不是 XMind 的完整复刻，也不是一个附带思维导图的 AI 聊天软件。

MindTree 是本地优先的个人树形工作空间，服务于四类连续行为：

1. 低成本记录当下发生的事情和想法。
2. 在项目或学习过程中逐步形成结构。
3. 让智能体识别值得继续推进或长期保存的内容。
4. 在用户确认后，将过程信息回流为项目状态、任务、决策和知识。

## 2. 设计初心

用户已经意识到自身存在两类长期困难：

- 对过程的持续记录不足。
- 对结果的阶段沉淀不足。

产品不应通过增加纪律要求来纠正用户，例如强迫用户每天填写完整模板、在记录前选择严格类型或手工整理所有节点。产品应利用用户已经能够自然产生的日报、临时节点、学习笔记和项目记录，补全其后的识别、整理、回流与复用过程。

因此核心原则是：

> 不要求用户先成为更会记录的人，而是让系统把已有记录转化为更可持续的行动与知识资产。

## 3. 核心价值

### 3.1 降低记录门槛

用户可以先写下不完整、混合类型、尚未分类的内容。快速记录不应被工作流阻塞。

### 3.2 保留真实过程

日报、周报、会议原话和临时判断具有时间语境。系统应保留原始节点，不能用整理后的结论替换它们。

### 3.3 发现过程中的稳定信息

智能体从记录中识别：

- 已完成成果
- 待办事项
- 未解决问题和风险
- 已形成决策
- 可复用知识
- 值得保留的想法

### 3.4 让信息回到正确位置

按日期记录的项目进展应能回流项目；学习过程中的稳定结论应能回流知识主题；临时想法应能保留并在未来关联到合适项目。

### 3.5 保持用户控制权

智能体负责发现、建议和准备修改，用户决定是否写入。写入必须可查看、可修改、可撤销、可追溯。

## 4. 产品与普通思维导图的区别

普通思维导图主要帮助用户表达已经形成的结构。MindTree 还应帮助用户从零散过程逐渐形成结构：

```text
普通导图：想清楚 → 画出来
MindTree：先记录 → 边行动边形成结构 → 沉淀并再次使用
```

## 5. 两个智能能力

### 5.1 智能沉淀

面向自然记录。回答：这段记录里有什么值得推进、归档或更新？

```text
记录 → 识别 → 候选 → 确认 → 回流
```

### 5.2 智能协作

面向明确任务。回答：围绕当前问题，如何探索、决策、交付并形成检查点？

```text
理解 → 决策 → 执行 → 验收 → 沉淀
```

两者共享同一个 Agent 和数据基础，但第一阶段优先实现智能沉淀。

## 6. 非目标

第一阶段明确不做：

- 自动整理和重写全部历史导图。
- 未经确认直接修改、移动或删除节点。
- 保存全部聊天流水作为知识。
- 以 AI 生成量作为产品价值指标。
- 强迫每张导图使用同一模板。
- 多 Agent 编排、无限自主循环。
- 向量数据库和复杂语义检索。
- 用工作流状态替代现有任务状态。

## 7. 成功标准

第一阶段成功不是“AI 能生成一棵很大的树”，而是：

1. 用户继续保持原有记录习惯。
2. 系统能够从混合记录中识别高价值候选。
3. 用户能在较少操作下接受、修改或忽略候选。
4. 确认后的内容能正确更新已有项目或知识，而非只会新增节点。
5. 用户未来能通过项目或知识树重新找到过去分散在日报中的信息。
