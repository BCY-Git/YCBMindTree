# 验收标准、测试样本与风险

## 1. 产品验收

### AC-01 不增加记录负担

未启用或未触发 AI 时，日报、随手记和普通导图编辑流程保持原样。

### AC-02 准确识别混合内容

给定一组包含成果、问题、任务、沟通和想法的日期节点，系统能生成不同类型候选，不把所有内容都处理为任务。

### AC-03 支持状态更新

候选可以完成已有任务、追加备注或更新已有节点，而不只能新增分支。

### AC-04 保留原始来源

应用沉淀后，源节点内容和结构不变；目标结果可追溯到源文档和源节点。

### AC-05 用户控制

未经确认不产生任何导图写入。用户可修改类型、动作、目标和写入文本。

### AC-06 原子与撤销

单文档批量应用要么全部成功，要么全部失败，并能作为一次操作撤销。

### AC-07 避免重复

同一源节点重复分析时，已经应用的同类候选不会默认再次创建。

### AC-08 AI 失败不破坏基础功能

未配置、超时、非法 JSON、空结果或服务错误均不影响保存与编辑。

## 2. 固定测试样本

测试夹具必须包含以下四类，不依赖真实 API：

### 日报样本

```text
7.14
- 下午修改无人项目 bug
- 手动分解和自动分解已完成
- AFSIM PPT 已完成并交付
- 地图瓦片路径仍需修改
```

期望至少识别：任务、成果、成果、问题/任务；不能全部分类为事实。

### 学习样本

```text
Zod
- 我的理解：它是 TypeScript 后面的第二道防线
- 核心定义：运行时验证数据是否符合 schema
- 待验证：多余字段默认如何处理
```

期望识别知识结论和待验证问题；不能标记为项目成果。

### 项目样本

```text
AFSIM PPT
- 初版已完成
- 汇报反馈：对比图太小，维度不足
- 下一步：重新设计第一页对比图
```

期望更新项目状态、创建问题和下一步任务。

### 临时想法样本

```text
可以让 AI 从视频中找关键帧并生成文字说明
```

期望识别 `idea`；目标不确定时允许为空。

## 3. 单元测试

- Zod 协议合法/非法输入。
- 代码围栏和脏 JSON 处理策略。
- ID 白名单。
- 节点数量和文本长度上限。
- 指纹稳定性。
- 重复候选判断。
- 候选到操作映射。
- 追加备注不覆盖原内容。
- 完成已完成任务的幂等性。
- 批量命令原子失败。

## 4. 集成测试

- 从当前子树构建上下文。
- 使用模拟模型响应生成批次。
- 编辑候选并预览。
- 应用后文档和来源记录一致。
- 撤销后文档恢复，来源状态按设计处理。
- 文档在预览期间改变时阻止过期写入。
- 删除目标节点后的错误提示。
- Dexie 旧版本升级。
- 工作区备份/恢复后的来源一致性。

## 5. UI 测试

- 键盘可操作候选列表。
- 目标缺失和重复提示清晰。
- 320px 等窄宽下不遮挡主要操作。
- 大量候选有合理上限，不产生内部复杂滚动嵌套。
- AI 配置缺失时给出可恢复提示。
- 普通导图界面没有新增永久噪声。

## 6. 真实使用指标

优先记录本地聚合指标，不上传原文：

- 候选接受率。
- 接受前修改率。
- 忽略率。
- 目标重选率。
- 重复候选率。
- 应用失败率。
- 每次沉淀平均确认耗时。
- 沉淀结果被再次访问或更新的比例。

不要只追求接受率。高接受率可能来自候选过少；应结合“被再次使用”判断价值。

## 7. 主要风险

| 风险 | 缓解方式 |
| --- | --- |
| AI 制造过多节点 | 候选上限、默认保守、优先更新 |
| 错误结论长期化 | 来源、预览、用户确认 |
| 重复沉淀 | 指纹、目标相似检查、已应用记录 |
| 导图被工作流污染 | 独立批次表、普通节点不显示元数据 |
| 跨文档半写入 | Dexie 事务、版本检查 |
| 上下文泄露 | 最小范围、无附件/Key、可见分析范围 |
| 代码复杂度集中在组件 | 拆分领域服务与 UI |

## 8. 发布门槛

进入真实使用前必须满足：

- 所有协议与命令单测通过。
- 旧数据库升级测试通过。
- 普通编辑、撤销、导入导出和备份回归通过。
- 单文档原子写入验证通过。
- 四类固定样本人工审查结果可接受。
- AI 不可用时应用仍可完整使用。
