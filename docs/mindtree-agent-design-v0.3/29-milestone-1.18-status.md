# 里程碑 1.18：项目状态视图与智能回流闭环

更新时间：2026-07-17

## 目标

把已经存在的“分析 → 候选 → 用户确认 → 写入并保留来源”能力，呈现为用户能够持续使用的项目工作视图。重点不是新增一个项目管理系统，而是让按日期保存的过程信息在项目节点上变得可读、可追溯。

## 已完成

- 新增 `src/projects/project-status.ts`：从项目分支、任务状态、已应用沉淀批次、来源记录与活跃协作会话派生项目状态。
- 项目范围严格限定在当前选择节点的子树，其他项目和未写入的候选不会污染当前状态。
- 汇总项目目标、任务进度、进行中任务、风险、项目成果、已确认决策与下一步。
- 右侧检查器增加“项目”页；使用普通工作信息布局，避免新增独立仪表盘或第二套项目字段。
- 每条带来源的沉淀支持跳回原始导图和节点，保留日报、会议原话等时间语境。
- 状态刷新只重读本地记录，不改变节点、不触发模型请求、不覆盖原文。

## 数据与安全边界

- 项目状态是派生数据，不进入 `MindMapDocument` schema，也不会影响同步、导出或撤销历史。
- 只使用候选状态为 `applied`、且能匹配来源记录的沉淀；`pending`、`accepted`、`ignored`、`failed` 一律不展示为正式项目进展。
- 沉淀来源仍然是唯一事实依据；状态页只提供入口，不复制完整原文。
- 此里程碑不加入自动写入、自动重组项目、全历史重分析或无限 Agent 循环。

## 验收

- 领域测试覆盖：任务与已确认成果/问题/决策的合并、协作下一步、范围隔离与待确认候选排除。
- 组件测试覆盖：项目状态信息展示、来源回跳和刷新行为。
- 全部前端测试和生产构建通过。

## 后续建议

下一阶段可从“项目状态”继续做低干扰提醒：当日报新增多个结果、问题或下一步但尚未回流时，只提示用户生成沉淀建议；仍由用户确认，不自动修改项目树。
