# 智能沉淀 MVP 功能规格

## 1. 目标

让用户从当前节点或子树发起分析，得到结构化的待沉淀候选；用户可以调整类型、目标位置和动作，确认后一次性写入，且可撤销、可追溯、不会重复处理。

## 2. MVP 范围

### 必须具备

- 分析当前节点或当前子树。
- 七类候选识别。
- 候选收件箱。
- 建议目标文档与父节点。
- 支持 `keep`、`create`、`update`、`complete`、`append-note`。
- 逐条接受/忽略、批量接受。
- 写入前差异预览。
- 一次确认作为一次撤销单位。
- 来源记录与重复检测。
- AI 输出 Zod 校验、节点存在性检查和版本检查。

### 可以延后

- 后台自动定时分析。
- 跨设备候选同步。
- 跨图可视化关系线。
- 自动重新分析全部历史日报。
- 基于向量的目标推荐。
- 完整协作会话状态机。

## 3. 用户入口

第一版提供两个明确入口：

1. 节点/画布菜单：`分析可沉淀内容`。
2. AI 助手：`生成沉淀建议`。

可选快捷入口：随手记离开时显示“稍后整理”，但不自动调用模型。

## 4. 分析范围

用户发起时明确显示：

- 当前节点
- 当前子树
- 整张导图（第一版可隐藏或限制节点数）

默认使用当前子树。超过上下文预算时，先本地裁剪并明确提示实际分析范围。

## 5. 候选生命周期

```text
generating → pending → accepted/ignored → applied
                       ↘ failed
```

- `pending`：等待用户审查。
- `accepted`：已选择但尚未写入。
- `ignored`：本次忽略；保留去重指纹。
- `applied`：已写入并记录操作结果。
- `failed`：目标变化、版本冲突或命令失败。

## 6. 候选动作

### keep

只保留源记录，不向其他位置写入。适用于普通事实或暂不确定内容。

### create

在建议父节点下创建新节点或分支。

### update

更新已有节点主题、备注或语义字段。第一版主题更新必须谨慎，默认优先更新备注。

### complete

将已有任务更新为 `done`，可在备注追加完成依据。

### append-note

将新信息以带日期或来源的段落追加到已有节点备注，不覆盖原内容。

## 7. 目标推荐

第一版不需要语义向量搜索，可使用：

1. 当前文档标题、分类和节点路径。
2. 本地文档列表。
3. 标题/关键词匹配。
4. 最近访问或最近更新。
5. AI 在有限候选列表中选择目标。

AI 不得编造文档 ID 或节点 ID，只能从上下文提供的候选中选择；找不到时返回 `null`。

## 8. 重复检测

至少使用以下组合生成指纹：

```text
sourceDocumentId + sourceNodeId + normalizedCandidateTitle + candidateType
```

写入前再次检查：

- 源节点是否已产生相同已应用候选。
- 目标位置是否存在同名或高相似节点。
- `complete` 的目标是否已经完成。

检测到可能重复时，不直接拦截，候选标记“可能重复”并默认不选中。

## 9. 批量应用

一次确认中的所有操作必须：

- 先完成全部校验。
- 生成完整预览。
- 作为一个原子命令写入当前文档。
- 跨文档时使用事务；任一失败则不产生半完成结果。
- 返回每条候选的实际目标与操作结果。

## 10. 空结果与失败

- 没有高价值内容：显示“未发现需要沉淀的内容”，不生成填充节点。
- 模型格式错误：保留用户输入，显示可重试错误。
- 目标已删除：要求重新选择，不静默改到其他位置。
- 文档已变化：重新校验；存在冲突时重新生成预览。
- API 未配置：不影响普通导图和记录功能。

## 11. 质量原则

- 宁可少提取，不要制造大量低价值节点。
- 宁可目标为空，不要编造去向。
- 宁可建议追加备注，不要轻易改写用户标题。
- 不把聊天内容原样复制为长期知识。
- 不把尚未决定的内容标记为决策。
